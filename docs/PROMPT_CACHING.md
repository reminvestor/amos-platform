# AWS Bedrock Prompt Caching

This document explains how to configure and use prompt caching with AWS Bedrock to reduce token costs by up to 49%.

## What is Prompt Caching?

Prompt caching allows you to cache static components of your prompts (system prompt and tool definitions) for up to 5 minutes. When cached content is reused, you get a **90% discount** on those tokens.

**Token Pricing**:
- Normal input tokens: $7.50 per 1M tokens
- Cache write (first request): $9.37 per 1M tokens (25% premium)
- Cache read (subsequent requests): $0.75 per 1M tokens (90% discount)

**AMOS Prompt Breakdown**:
- System prompt: ~7,000 tokens (static)
- Tool definitions: ~2,500 tokens (static)
- Conversation: ~8,000 tokens (varies)
- **Total cacheable: 9,500 tokens**

## Cost Savings Example

**Without Caching** (per request):
- System prompt: 7,000 tokens × $0.0000075 = $0.0525
- Tools: 2,500 tokens × $0.0000075 = $0.01875
- Conversation: 8,000 tokens × $0.0000075 = $0.06
- **Total: $0.13125 per request**

**With Caching** (second request onwards):
- System prompt (cached): 7,000 tokens × $0.00000075 = $0.00525
- Tools (cached): 2,500 tokens × $0.00000075 = $0.001875
- Conversation: 8,000 tokens × $0.0000075 = $0.06
- **Total: $0.06713 per request**

**Savings**: $0.06412 per request (49% reduction)

**Monthly Savings** (assuming 1,000 requests/day):
- 1,000 requests/day × $0.06412 = **$64/day**
- 30 days × $64 = **$1,920/month**

## Configuration

### Enable/Disable Prompt Caching

In your `.env` file:

```bash
# Enable prompt caching (default: true)
BEDROCK_PROMPT_CACHING_ENABLED=true

# Disable prompt caching (use latest models without caching)
BEDROCK_PROMPT_CACHING_ENABLED=false
```

**Default**: If not set, caching is **enabled** (true).

## Model Endpoint Trade-off

AWS Bedrock has two types of endpoints:

### Regional Endpoints (Supports Caching)
- Format: `us.anthropic.*`
- Examples:
  - `us.anthropic.claude-3-5-sonnet-20241022-v2:0` (Sonnet 3.5 v2)
  - `us.anthropic.claude-opus-4-1-20250805-v1:0` (Opus 4.1)
  - `us.anthropic.claude-3-5-haiku-20241022-v1:0` (Haiku 3.5)
- **Supports**: Prompt caching ✅
- **Models**: Stable versions (3.5 Sonnet v2, Opus 4.1, Haiku 3.5)

### Global Endpoints (No Caching)
- Format: `global.anthropic.*`
- Examples:
  - `global.anthropic.claude-sonnet-4-5-20250929-v1:0` (Sonnet 4.5)
- **Supports**: Prompt caching ❌
- **Models**: Latest versions (Sonnet 4.5)

## When Caching is Enabled

**Model Mappings**:
- `claude-sonnet-4-5` → `us.anthropic.claude-3-5-sonnet-20241022-v2:0` (fallback to 3.5 v2)
- `claude-3-5-sonnet` → `us.anthropic.claude-3-5-sonnet-20241022-v2:0`
- `claude-opus-4-1` → `us.anthropic.claude-opus-4-1-20250805-v1:0`
- `claude-3-haiku` → `us.anthropic.claude-3-5-haiku-20241022-v1:0`

**Behavior**:
- System prompt is cached (separate `cachePoint` after text)
- Tool definitions are cached (separate `cachePoint` after all tools)
- Cache TTL: 5 minutes (resets on each hit)
- Cache key: Automatically generated by AWS based on content

**Logs**:
```
💾 Prompt caching enabled for system prompt (~7000 tokens)
💾 Prompt caching enabled for tools (~2500 tokens)
💰 Token usage - Input: 8000, Output: 450 | Cache: 9500 read (54.3% hit rate), 0 written | Savings: ~8550 tokens ($0.0641)
```

## When Caching is Disabled

**Model Mappings**:
- `claude-sonnet-4-5` → `global.anthropic.claude-sonnet-4-5-20250929-v1:0` ✅
- `claude-3-5-sonnet` → `global.anthropic.claude-3-5-sonnet-20241022-v2:0`
- `claude-opus-4-1` → `global.anthropic.claude-opus-4-1-20250805-v1:0`
- `claude-3-haiku` → `global.anthropic.claude-3-5-haiku-20241022-v1:0`

**Behavior**:
- No `cachePoint` markers added
- System prompt sent as simple array
- Tools sent without cache checkpoint
- Full token costs apply ($7.50/1M)

**Logs**:
```
✅ Using Sonnet 4.5 (global endpoint, no caching)
🔧 Sending 23 tools to Claude (no caching): get_data, create_object, ...
Token usage - Input: 17500, Output: 450
```

## Decision Guide

**Use Caching (BEDROCK_PROMPT_CACHING_ENABLED=true) if**:
- Cost optimization is a priority
- You're okay with Sonnet 3.5 v2 (still very capable)
- High request volume (1000+ requests/day)
- Long conversation threads (cache persists for 5 minutes)

**Disable Caching (BEDROCK_PROMPT_CACHING_ENABLED=false) if**:
- You need the absolute latest model (Sonnet 4.5)
- Cutting-edge features are critical
- Low request volume (cost savings minimal)
- Budget is not a concern

## How Cache Lifecycle Works

**First Request** (Cache Creation):
```
Request 1 at 10:00:00 AM
- System prompt: 7,000 tokens (write to cache)
- Tools: 2,500 tokens (write to cache)
- Conversation: 8,000 tokens (not cached)
- Cost: $0.13125 (slightly higher due to cache write)
- Cache TTL: Expires at 10:05:00 AM
```

**Second Request** (Cache Hit):
```
Request 2 at 10:02:00 AM
- System prompt: 7,000 tokens (read from cache - 90% discount)
- Tools: 2,500 tokens (read from cache - 90% discount)
- Conversation: 8,000 tokens (not cached)
- Cost: $0.06713 (49% savings!)
- Cache TTL: Resets to 10:07:00 AM
```

**Cache Miss** (After TTL Expires):
```
Request 3 at 10:10:00 AM (cache expired at 10:07:00)
- Creates new cache (like Request 1)
- Cost: $0.13125
- Cache TTL: Expires at 10:15:00 AM
```

## Technical Details

### Cache Requirements
- Minimum 1,024 tokens per cache checkpoint
- Maximum 4 checkpoints per request
- Cache key: SHA256 hash of content (automatic)

### Cache Format
```ruby
# System prompt caching
payload[:system] = [
  { text: system_prompt },
  { cachePoint: { type: "default" } }
]

# Tools caching
formatted_tools = format_tools_for_bedrock(tools)
formatted_tools << { cachePoint: { type: "default" } }
```

### Response Fields
- `cache_write_input_tokens_count`: Tokens written to cache (first request)
- `cache_read_input_tokens_count`: Tokens read from cache (subsequent requests)

## Troubleshooting

**Error: "unexpected value at params[:system][1][:cachePoint]"**
- You're using a global endpoint which doesn't support caching
- Solution: Set `BEDROCK_PROMPT_CACHING_ENABLED=true` or verify regional endpoint

**Logs show 0 cache reads on second request**
- Cache expired (5 minute TTL exceeded)
- Different session (cache is per-content, not per-user)
- Content changed (system prompt or tools modified)

**Still seeing full token costs**
- Verify `BEDROCK_PROMPT_CACHING_ENABLED=true` in `.env`
- Check logs for `💾 Prompt caching enabled` messages
- Ensure using regional endpoints (`us.anthropic.*`)
